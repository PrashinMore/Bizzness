# Security Policy

## Supported versions

Security fixes are applied on a best-effort basis to the latest `main` branch.
Please upgrade to the newest available release when advisories are published.

| Version | Supported |
| --- | --- |
| `main` / latest | Yes |
| Older tagged releases | Best effort |

## Reporting a vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.**

Report privately by emailing:

- **Primary:** [security@ezcommerse.com](mailto:security@ezcommerse.com) _(placeholder — replace with a monitored inbox)_
- **Fallback:** [prashin@ezcommerse.com](mailto:prashin@ezcommerse.com)

Include as much detail as you can:

- Description of the issue and potential impact
- Steps to reproduce or a proof of concept
- Affected component (API, web, mobile) and version / commit if known
- Whether you are aware of active exploitation

## What to expect

| Step | Target timing |
| --- | --- |
| Acknowledgement | Within **3 business days** |
| Initial assessment | Within **7 business days** |
| Fix / mitigation plan | Depends on severity; we will keep you updated |

We will credit reporters who wish to be acknowledged (unless you prefer to remain anonymous).

## Safe harbor

We welcome good-faith research. Avoid privacy violations, destruction of data, and disruption of production services (including the public demo) beyond what is necessary to demonstrate the issue.
